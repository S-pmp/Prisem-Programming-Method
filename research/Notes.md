# Note 001

## コードより構造

AIによるコード生成を観察していて感じたこと。

同じ機能は複数の言語で実装できる。

- PHP
- Java
- Python
- JavaScript

しかし実装が違っても意味は同じ場合がある。

その場合、本質はコードではなく構造に存在する可能性がある。

---

# Note 002

## DBは巨大な図書館である

DBを調査した結果、DBは単なる保存装置というより、意味を保管する図書館に近いと感じた。
システムが守りたいものは、コードではなく情報である場合が多い。

---

# Note 003

## 攻撃者は何を狙うのか

セキュリティを見ていて感じたこと。攻撃者はコードを読みたいわけではない。

最終的に欲しいものは、

- 顧客情報
- 認証情報
- 決済情報
- 設計情報

であることが多い。つまり、侵入そのものではなく、価値への到達が目的である可能性が高い。

# Note 005

## 認証と権限は別である

認証は、「誰なのか」を確認する。

権限は、「何ができるのか」を決める。

実際の制御は認証ではなく権限によって行われているように見える。

---

# Note 006

## なぜ監視が必要になるのか

監視は重要である。

しかし監視の必要性そのものについて考える価値がある。

監視対象は、

- 権限
- 結合
- 依存関係
- 例外処理

の増加と関係している可能性がある。

監視は原因ではなく結果かもしれない。

---

# Note 007

## パッチはなぜ終わらないのか

既存システムは継続的に更新され続けている。

- セキュリティパッチ
- 不具合修正
- 依存関係更新

なぜ終わらないのか。

結合や依存関係の増加が原因の一部である可能性がある。

---

# Note 008

## OAuthから得た気付き

OAuthを調べていて感じたこと。

本当に必要なのは本人の全情報ではなく、本人確認済みという意味ではないか。

つまり、情報全体ではなく意味だけを受け渡すという考え方が存在する。

---

# Note 009

## APIは意味の受け渡し装置かもしれない

APIは機能共有ではなく、

意味共有として見ることもできる。

配送APIは配送の意味を渡している。

認証APIは本人確認の意味を渡している。

APIを構造として見ると、意味の移動経路として理解できる可能性がある。

---

# Note 010

## LinuxとPMP

Linuxを調べていて感じたこと。

LinuxはCPU、メモリ、ディスク、ネットワークを管理する。

PMPは意味、権限、経路、責任を管理しようとしている。

管理対象は違うが、

責務分離という考え方には共通性があるように見える。
